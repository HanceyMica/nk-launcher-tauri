## P1（体验/一致性）

### P1-1 简单模式：数字命中后的提示列表文案与 prompt 示例不一致（条款 5）

- **现状**
  - 简单模式数字命中后，直接以通用 `renderResults([entry])` 方式展示结果项（图标 + title + desc）。
  - 相关位置：`src/index.ts` 的 simple 模式数字输入分支与 `renderResults`。
- **缺口/风险**
  - prompt 示例要求形如：
    - `1：跳转到 百度`
    - `2：打开 QQ`
    - `31：跳转到 Google`
  - 现有 UI 文案不满足示例描述（可能影响验收对照）。
- **建议实现点（落点）**
  - 为简单模式数字命中新增“提示行”渲染：根据 entry.kind 生成“跳转到/打开”的语句，并在回车后执行。
  - 相关文件：`src/index.ts`
- **验收要点**
  - 输入 `1` 后显示“1：跳转到 xxx”，回车才执行；输入 `3` 直接切换子网格无需回车（现有行为需确保不被破坏）。

### P1-2 首次启动 Welcome：独立 Welcome 页/引导占位（条款 9）

- **现状**
  - 首次启动通过 `get_has_launched` 判断后，直接打开配置窗的关于面板（`about-content`），并 `mark_launched`。
- **缺口/风险**
  - 不满足“首次启动：显示 Welcome 页（可使用占位符内容）”的表述；目前更像“打开关于”。
- **建议实现点（落点）**
  - 增加独立的 `welcome-content`（侧栏或单独 overlay 均可），包含占位的引导内容与“开始使用/关闭”动作。
  - 相关文件：
    - `index.html`（新增 welcome 面板结构）
    - `src/index.ts`（首次启动分支改为打开 welcome）
- **验收要点**
  - 首次启动显示 Welcome，引导完成后标记已启动；再次启动显示“按下 Alt+Space 初始页面”。
